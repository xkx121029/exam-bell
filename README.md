# 考试自动打铃 (ExamBell)

一个面向学校考务人员的 Windows 桌面小工具：排好一天的考试场次，程序会按北京时间自动播放三段提示音频，无需人工守点。

单文件 exe，**不依赖任何运行时**（不需要 .NET / VC++ 运行库），拷贝到 Win7 及以上的机器直接双击即可。

---

## 项目简介

考试打铃通常依赖人工看表、手动播放，稍有疏忽就可能响铃过早或漏响。ExamBell 用一个单文件 exe 解决了这个问题：

- 用日期时间选择器排入考试场次（可连续添加多场），程序自动按时间先后排序；
- 点击"启动监测"后，为每一场自动排好三个打铃节点，到点依次播放；
- 全部节点触发后自动复位，可立即继续排下一场。

`dist\ExamBell.exe` 约 920 KB，静态链接，只调用系统自带 DLL，**零安装**。

## 功能特性

### 多场考试

- 每场只需给出「考试名称 + 开始时间」，三个打铃节点自动推导，无需逐条录入；
- 最多可排 24 场，按开始时间升序排列；同一时刻不允许重复添加；
- 左侧日程列表实时显示每场的开始时间与汇总状态（未开始 / 待触发 / 播放中 / 已完成 / 已错过 / 已取消）；
- 在列表中单击即可切换下方节点面板展示的场次；「删除选中」与「清空日程」用于整理日程（清空需二次确认）；
- 已过期（超出 60 秒容差）的场次在启动时自动跳过并写入日志，不影响其它场次。

### 时间选择

开始时间使用系统日期时间选择器（`yyyy-MM-dd HH:mm`），下拉即可选日期与时、分，秒固定为 `00`，避免手输格式错误；「现在 +30」一键填入半小时后的整分钟，便于快速演示或临时排课。

### 三段自动打铃

| 节点 | 相对考试开始时间 | 默认提示内容 |
| --- | --- | --- |
| 第一段 | 提前 10 分钟 | 考生进入考场 |
| 第二段 | 提前 5 分钟 | 下发试卷与答题卡 |
| 第三段 | 考试开始 | 考生开始作答 |

三段音频可分别指定，互不影响。

### 北京时间基准

启动时按顺序向多个公开时间源发起校时请求，任一成功即停止：

| 顺序 | 时间源 | 接口 | 精度 |
| --- | --- | --- | --- |
| 1 | 淘宝 | `http://api.m.taobao.com/rest/api3.do?api=mtop.common.getTimestamp` | 毫秒 |
| 2 | 苏宁 | `http://quan.suning.com/getSysTime.do` | 秒 |
| 3 | 百度 | `http://www.baidu.com/`（读取响应的 `Date` 头） | 秒 |

- 记录请求发出与收到响应的本地时间，按**往返时延取中值**换算出北京时间与本地时间的偏移量；
- 之后用 `GetTickCount64()` 单调递增的计时推算当前时间，**运行中系统时间被改动也不影响打铃时刻**；
- 单个源不可达（DNS 解析失败、被校园网拦截、接口限流返回 403）时自动换下一个源，界面上标注实际命中的源，例如"已同步（苏宁）· 偏差 -2 ms"；
- 三个源全部不可用时，界面以红字提示"未同步 · 使用本机时间"，自动回退到本机时钟继续工作；
- 系统从休眠恢复时自动重新校时；启动监测时若距上次校时不超过 2 分钟则直接复用，避免对同一源连发请求被限流。

### 急停

界面下半部分是一块大面积红色按钮，也可直接按 `Esc`，立即停止正在播放的音频并取消全部后续节点。

### 无人值守

启动监测后无需再操作。所有场次的全部节点触发完毕后，程序自动复位状态，可继续排下一批考试。

### 60 秒容差

若某个节点已过但不足 60 秒（例如启动稍晚），程序会**立即补响**，不会直接跳过；超过 60 秒才标记为"已错过"。

### 配置持久化

全部考试场次与三段音频路径保存在：

```
%APPDATA%\ExamBell\config.ini
```

下次启动自动回填，无需重复设置。

### 音频自动识别

除了手动选择，也可以把音频文件放进 exe 同级的 `audio` 目录，并以 `01`、`02`、`03` 开头命名，程序会自动识别对应节点。

### 未设置音频时的兜底

没有选择音频文件时，程序退化为播放系统提示音，保证节点到点一定有声音。

## 运行环境

- 操作系统：Windows 7 SP1 x64（Windows 10 / 11 亦可正常运行）
- 运行库：**无**。不依赖 .NET、VC++ 运行库或任何第三方 DLL
- 依赖的系统组件：`KERNEL32 / USER32 / GDI32 / COMCTL32 / comdlg32 / WINHTTP / WINMM / msvcrt`（均为 Windows 自带）
- 无需管理员权限

可用如下命令核对依赖清单：

```bash
objdump -p dist/ExamBell.exe | grep "DLL Name"
```

## 快速开始

1. 下载并解压 release 中的 `ExamBell.exe`（或在仓库中直接取 `dist\ExamBell.exe`）。
2. 双击运行。
3. 在「考试名称」里填一个便于识别的名字（如"语文"），用日期时间选择器选定开始时间。
4. 点击「添加到日程」。重复第 3、4 步可连续排入多场，列表会自动按时间排序。
5. 依次为三个节点选择音频文件（支持 WAV / MP3 / WMA）。如果音频固定不变，可改用 `audio` 目录自动识别方式（见下文）。
6. 点击「启动监测」。顶部会显示距下一声铃的倒计时，列表与节点面板同步显示各场状态。
7. 如需中止，点击红色急停按钮或按 `Esc`。

> 建议在正式使用前用一场模拟时间完整走一遍流程，确认音频音量与播放设备正确。

## 源码构建

源码为单个 C++ 文件 [src-native/exambell.cpp](src-native/exambell.cpp)，只使用 Win32 API，不引入第三方库。使用 MinGW-w64 静态链接编译，仓库内提供了 `build.ps1`：

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

脚本等价于以下两步：

```bash
# 1) 编译图标与清单资源
windres -I src-native -O coff -o res.o src-native/exambell.rc

# 2) 静态链接生成 exe（产物无任何第三方运行时依赖）
g++ -O2 -mwindows -municode -static -static-libgcc -static-libstdc++ \
    -o dist/ExamBell.exe src-native/exambell.cpp res.o \
    -lwinhttp -lwinmm -lcomctl32 -lgdi32 -luser32
```

> 说明：本项目自带清单（启用 comctl32 v6 视觉样式与 DPI 感知），而 MinGW-w64 的 gcc 会自动链接 `default-manifest.o`，两者在 `ld` 合并资源时冲突并报 `multiple non-default manifests`。`build.ps1` 会在链接期间临时移开该文件、链接结束后立刻还原；手工编译时如遇到该报错，按同样方式处理即可。

产物为 `dist\ExamBell.exe`，可直接分发给任何 Win7 SP1 x64 及以上的机器。

## 配置说明

配置文件路径：`%APPDATA%\ExamBell\config.ini`，UTF-8 编码，格式为 `键=值`：

```ini
# 考试自动打铃 配置文件
examCount=2
exam0_name=语文
exam0_time=2026-10-30 09:00
exam1_name=数学
exam1_time=2026-10-30 14:30
audio0=D:\audio\enter.wav
audio1=D:\audio\paper.mp3
audio2=D:\audio\begin.wav
```

| 键 | 说明 |
| --- | --- |
| `examCount` | 场次数量（仅作说明，实际以 `examN_*` 键为准） |
| `examN_name` | 第 N 场的名称（N 从 0 开始） |
| `examN_time` | 第 N 场的开始时间，格式 `YYYY-MM-DD HH:MM` |
| `audio0` | 第一段（考前 10 分钟）音频完整路径 |
| `audio1` | 第二段（考前 5 分钟）音频完整路径 |
| `audio2` | 第三段（考试开始）音频完整路径 |

旧版的单场配置（只有 `start=YYYY-MM-DD HH:MM:SS` 一个键）仍可读取，会自动转为一场「第 1 场」。

### 音频目录自动识别

在 `ExamBell.exe` 同级创建 `audio` 文件夹，放入文件名以下列前缀开头的音频：

```
audio\
├─ 01_考生进场.wav
├─ 02_下发试卷.mp3
└─ 03_开始作答.wav
```

程序按 `01` / `02` / `03` 前缀依次对应三个节点。配置文件中的路径优先级高于自动识别结果。

## 技术实现说明

### 1. 多场考试与节点排期

每场考试保存名称与开始时间，三个节点按 `start - 10min`、`start - 5min`、`start` 推导，不单独存储。启动监测时统一为所有场次生成节点时刻，`200 ms` 定时器轮询推进：

- 节点到达时刻后 60 秒内触发播放，超过 60 秒标记为"已错过"；
- 单场状态由三个节点汇总：有节点在播放即"播放中"，仍有待触发即"待触发"，全部结束再按完成 / 错过 / 取消收敛；
- 日程按开始时间升序维护，新增场次插入时自动归位，`config.ini` 中按同样顺序落盘。

### 2. 网络校时与高精度计时

按 淘宝 → 苏宁 → 百度 的顺序依次请求，每个源都有 3 秒超时，任一成功即停止（失败的源只影响耗时，不影响结果）。淘宝与苏宁返回时间字段，百度则读取响应的 `Date` 头。每个源都记录请求发出与收到响应的本地时间，用响应时刻回退一半时延作为参考时刻，再与服务器时间比较得到偏移量。之后：

```
当前时间 = 基准本地时间 + GetTickCount64 经过时间 + 偏移量
```

`GetTickCount64` 不随系统时间调整而跳变，因此运行中修改系统时间不会导致打铃提前或延后。所有源都失败时偏移量归零，按本机时钟继续工作。

### 3. 音频播放

调用 `winmm.dll` 的 MCI（`mciSendString`），先按扩展名自动打开，失败再依次尝试 `mpegvideo`、`waveaudio` 设备类型。不引入任何第三方库，系统自带解码即可播放 WAV / MP3 / WMA。

### 4. 急停

急停会停止当前 MCI 播放实例并关闭设备，同时把所有未触发节点标记为"已取消"，监测循环立即退出。`Esc` 与急停按钮走同一入口。

### 5. 界面

纯 Win32 原生控件：`SysDateTimePick32` 选日期时间、`LISTBOX`（`LBS_OWNERDRAWFIXED`）自绘日程行（名称、开始时间与状态胶囊），自绘按钮（`BS_OWNERDRAW` + `WM_DRAWITEM`），状态色块通过 `WM_CTLCOLORSTATIC` 上色。应用清单启用 comctl32 v6 视觉样式，运行时读取屏幕 DPI 并按比例缩放全部坐标，高 DPI 下不糊不挤。

## 已知限制

- 三个公开时间源都可能因网络策略、接口限流或接口变更而失效；全部失效时程序自动回退本机时间，此时打铃精度取决于本机时钟是否准确。
- 音频播放依赖系统默认输出设备，请在正式使用前确认音量与输出设备。
- 监测进行中日程处于锁定状态（防止误改导致调度错乱），需先急停或等待全部结束才能编辑。
- 最多可排 24 场，开始时间精确到分钟（秒固定为 `00`）。
