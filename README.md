# 考试自动打铃 (ExamBell)

一个面向学校考务人员的 Windows 桌面小工具：排好一天的考试场次，程序会按北京时间自动播放三段提示音频，无需人工守点。

单文件 exe，**不依赖任何运行时**（不需要 .NET / VC++ 运行库），拷贝到 Win7 及以上的机器直接双击即可。

---

## 项目简介

考试打铃通常依赖人工看表、手动播放，稍有疏忽就可能响铃过早或漏响。ExamBell 用一个单文件 exe 解决了这个问题：

- 用日期时间选择器排入考试场次（可连续添加多场），程序自动按时间先后排序；
- 点击"启动监测"后，为每一场自动排好三个打铃节点，到点依次播放；
- 监测进行中仍可继续添加新场次，无需急停；
- 全部节点触发后自动复位，可立即继续排下一场。

`dist\ExamBell.exe` 约 960 KB，静态链接，只调用系统自带 DLL，**零安装**。空闲时 CPU 占用约 `0%`、私有内存约 `4 MB`。

## 功能特性

### 多场考试

- 每场只需给出「考试名称 + 开始时间」，三个打铃节点自动推导，无需逐条录入；
- 最多可排 24 场，按开始时间升序排列；同一时刻不允许重复添加；
- 左侧日程列表实时显示每场的开始时间与汇总状态（未开始 / 待触发 / 播放中 / 已完成 / 已错过 / 已取消）；
- 在列表中单击即可切换下方节点面板展示的场次；「删除选中」与「清空日程」用于整理日程（清空需二次确认）；
- 已过期（超出 60 秒容差）的场次在启动时自动跳过并写入日志，不影响其它场次；
- **监测进行中可继续添加场次**：填写名称与时间后点「添加到日程」，新场次立即排入调度并参与倒计时，无需急停重来。

### 时间选择

开始时间使用自绘的时间选择器，不依赖系统日期控件：

- **点日历图标**弹出月历，支持翻月、今天高亮、悬停预览，点一下即选日期；
- **点数字段**选中年 / 月 / 日 / 时 / 分，再用滚轮或右侧上下箭头逐段微调；
- 键盘同样可用：`←` `→` 切换字段，`↑` `↓` 增减，`PgUp` `PgDn` 一次跨 5。

秒固定为 `00`，不会出现手输格式错误。

### 三段自动打铃

| 节点 | 相对考试开始时间 | 默认提示内容 |
| --- | --- | --- |
| 第一段 | 提前 10 分钟（两个间隔之和） | 考生进入考场 |
| 第二段 | 提前 5 分钟（第二个间隔） | 下发试卷与答题卡 |
| 第三段 | 考试开始（固定） | 考生开始作答 |

三段音频可分别指定，互不影响。

### 可调打铃间隔

同一场考试内相邻两次打铃的间隔不再写死，可在「打铃节点」面板底部直接修改：

- 两个数值分别对应「第 1→2 次」与「第 2→3 次」，单位分钟，取值范围 `1~60`；
- 第三次打铃始终锚定考试开始时刻，节点名称（如「考前 3 分钟」）与预定时间随之实时重算；
- 设置对所有场次通用，保存在配置文件中，下次启动沿用；
- 输入框失焦或点击「启动监测」时生效，非法输入自动夹取到 `1~60`；
- **监测进行中会锁定这两个输入框**——中途改间隔会让已经排期的节点时刻失去意义，需急停或等本轮结束后再调。

默认 `5 / 5` 分钟，与旧版的「提前 10 分钟 / 提前 5 分钟 / 开考」完全等价，升级后无需重新设置。

### 北京时间基准

启动时按顺序向多个公开时间源发起校时请求，任一成功即停止：

| 顺序 | 时间源 | 接口 | 精度 |
| --- | --- | --- | --- |
| 1 | 淘宝 | `http://api.m.taobao.com/rest/api3.do?api=mtop.common.getTimestamp` | 毫秒 |
| 2 | 苏宁 | `http://quan.suning.com/getSysTime.do` | 秒 |
| 3 | 百度 | `http://www.baidu.com/`（读取响应的 `Date` 头） | 秒 |

- 记录请求发出与收到响应的本地时间，按**往返时延取中值**换算出北京时间与本地时间的偏移量；
- 之后用 `GetTickCount64()` 单调递增的计时推算当前时间，**运行中系统时间被改动也不影响打铃时刻**；
- 单个源不可达（DNS 解析失败、被校园网拦截、接口限流返回 403）时自动换下一个源，界面上标注实际命中的源，例如"已同步（苏宁）· 偏差 -2 ms"；
- 三个源全部不可用时，界面以红字提示"未同步 · 使用本机时间"，自动回退到本机时钟继续工作；
- 系统从休眠恢复时自动重新校时；启动监测时若距上次校时不超过 2 分钟则直接复用，避免对同一源连发请求被限流。

### 急停

界面下半部分是一块大面积红色按钮，也可直接按 `Esc`，立即停止正在播放的音频并取消全部后续节点。

### 无人值守

启动监测后无需再操作。所有场次的全部节点触发完毕后，程序自动复位状态，可继续排下一批考试。

### 60 秒容差

若某个节点已过但不足 60 秒（例如启动稍晚），程序会**立即补响**，不会直接跳过；超过 60 秒才标记为"已错过"。

### 配置持久化

全部考试场次与三段音频路径保存在：

```
%APPDATA%\ExamBell\config.ini
```

下次启动自动回填，无需重复设置。

### 音频自动识别

除了手动选择，也可以把音频文件放进 exe 同级的 `audio` 目录，并以 `01`、`02`、`03` 开头命名，程序会自动识别对应节点。

支持 `WAV / MP3 / WMA / MP4 / M4A`。其中 WAV、MP3、WMA 走 MCI，MP4、M4A 走系统自带的 Media Foundation（只取声音轨，不会弹出视频窗口）。

### 未设置音频时的兜底

没有选择音频文件时，程序退化为播放系统提示音，保证节点到点一定有声音。

## 运行环境

- 操作系统：Windows 7 SP1 x64（Windows 10 / 11 亦可正常运行）
- 运行库：**无**。不依赖 .NET、VC++ 运行库或任何第三方 DLL
- 依赖的系统组件：`KERNEL32 / USER32 / GDI32 / COMCTL32 / comdlg32 / WINHTTP / WINMM / MFPlay / MFPlat / OLE32 / msvcrt`（均为 Windows 自带）
- 无需管理员权限

可用如下命令核对依赖清单：

```bash
objdump -p dist/ExamBell.exe | grep "DLL Name"
```

## 快速开始

1. 下载并解压 release 中的 `ExamBell.exe`（或在仓库中直接取 `dist\ExamBell.exe`）。
2. 双击运行。
3. 在「考试名称」里填一个便于识别的名字（如"语文"），用时间选择器选定开始时间。
4. 点击「添加到日程」。重复第 3、4 步可连续排入多场，列表会自动按时间排序。
5. 依次为三个节点选择音频文件（支持 WAV / MP3 / WMA / MP4 / M4A），按需调整面板底部的打铃间隔。如果音频固定不变，可改用 `audio` 目录自动识别方式（见下文）。
6. 点击「启动监测」。顶部会显示距下一声铃的倒计时，列表与节点面板同步显示各场状态。
7. 监测进行中如需补排场次，直接填名称与时间点「添加到日程」即可，无需急停。
8. 如需中止，点击红色急停按钮或按 `Esc`。

> 建议在正式使用前用一场模拟时间完整走一遍流程，确认音频音量与播放设备正确。

## 源码构建

源码为单个 C++ 文件 [src-native/exambell.cpp](src-native/exambell.cpp)，只使用 Win32 API，不引入第三方库。使用 MinGW-w64 静态链接编译，仓库内提供了 `build.ps1`：

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

脚本等价于以下两步：

```bash
# 1) 编译图标与清单资源
windres -I src-native -O coff -o res.o src-native/exambell.rc

# 2) 静态链接生成 exe（产物无任何第三方运行时依赖）
g++ -O2 -mwindows -municode -static -static-libgcc -static-libstdc++ \
    -o dist/ExamBell.exe src-native/exambell.cpp res.o \
    -lwinhttp -lwinmm -lcomctl32 -lgdi32 -luser32
```

> 说明：本项目自带清单（启用 comctl32 v6 视觉样式与 DPI 感知），而 MinGW-w64 的 gcc 会自动链接 `default-manifest.o`，两者在 `ld` 合并资源时冲突并报 `multiple non-default manifests`。`build.ps1` 会在链接期间临时移开该文件、链接结束后立刻还原；手工编译时如遇到该报错，按同样方式处理即可。

产物为 `dist\ExamBell.exe`，可直接分发给任何 Win7 SP1 x64 及以上的机器。

## 配置说明

配置文件路径：`%APPDATA%\ExamBell\config.ini`，UTF-8 编码，格式为 `键=值`：

```ini
# 考试自动打铃 配置文件
examCount=2
exam0_name=语文
exam0_time=2026-10-30 09:00
exam1_name=数学
exam1_time=2026-10-30 14:30
audio0=D:\audio\enter.wav
audio1=D:\audio\paper.mp3
audio2=D:\audio\begin.wav
gap1=5
gap2=5
```

| 键 | 说明 |
| --- | --- |
| `examCount` | 场次数量（仅作说明，实际以 `examN_*` 键为准） |
| `examN_name` | 第 N 场的名称（N 从 0 开始） |
| `examN_time` | 第 N 场的开始时间，格式 `YYYY-MM-DD HH:MM` |
| `audio0` | 第一段（考前 `gap1+gap2` 分钟）音频完整路径 |
| `audio1` | 第二段（考前 `gap2` 分钟）音频完整路径 |
| `audio2` | 第三段（考试开始）音频完整路径 |
| `gap1` | 第 1→2 次打铃的间隔（分钟，`1~60`，缺省 5） |
| `gap2` | 第 2→3 次打铃的间隔（分钟，`1~60`，缺省 5） |

旧版的单场配置（只有 `start=YYYY-MM-DD HH:MM:SS` 一个键）仍可读取，会自动转为一场「第 1 场」。

### 音频目录自动识别

在 `ExamBell.exe` 同级创建 `audio` 文件夹，放入文件名以下列前缀开头的音频：

```
audio\
├─ 01_考生进场.wav
├─ 02_下发试卷.mp3
└─ 03_开始作答.wav
```

程序按 `01` / `02` / `03` 前缀依次对应三个节点。配置文件中的路径优先级高于自动识别结果。

## 技术实现说明

### 1. 多场考试与节点排期

每场考试保存名称与开始时间，三个节点按 `start - (gap1+gap2)`、`start - gap2`、`start` 推导，不单独存储（`gap1`、`gap2` 为界面里可调的两次间隔，默认 5 / 5 分钟）。启动监测时统一为所有场次生成节点时刻，`200 ms` 定时器轮询推进：

- 节点到达时刻后 60 秒内触发播放，超过 60 秒标记为"已错过"；
- 单场状态由三个节点汇总：有节点在播放即"播放中"，仍有待触发即"待触发"，全部结束再按完成 / 错过 / 取消收敛；
- 日程按开始时间升序维护，新增场次插入时自动归位，`config.ini` 中按同样顺序落盘。

### 2. 网络校时与高精度计时

按 淘宝 → 苏宁 → 百度 的顺序依次请求，每个源都有 3 秒超时，任一成功即停止（失败的源只影响耗时，不影响结果）。淘宝与苏宁返回时间字段，百度则读取响应的 `Date` 头。每个源都记录请求发出与收到响应的本地时间，用响应时刻回退一半时延作为参考时刻，再与服务器时间比较得到偏移量。之后：

```
当前时间 = 基准本地时间 + GetTickCount64 经过时间 + 偏移量
```

`GetTickCount64` 不随系统时间调整而跳变，因此运行中修改系统时间不会导致打铃提前或延后。所有源都失败时偏移量归零，按本机时钟继续工作。

### 3. 音频播放

WAV / MP3 / WMA 调用 `winmm.dll` 的 MCI（`mciSendString`），先按扩展名自动打开，失败再依次尝试 `mpegvideo`、`waveaudio` 设备类型。

MCI 的 `mpegvideo` 只认 MPEG-1，放不了 MP4，因此 MP4 / M4A 改走系统自带的 Media Foundation（`MFPCreateMediaPlayer`，Windows 7 起随系统提供）。播放器窗口句柄传 `NULL`，只出声不出画面。两套引擎共用同一个「是否正在播放」判定与播放看门狗，任一引擎失败都会退回系统提示音。不引入任何第三方库。

### 4. 急停

急停会停止当前 MCI 播放实例并关闭设备，同时把所有未触发节点标记为"已取消"，监测循环立即退出。`Esc` 与急停按钮走同一入口。

### 5. 界面

纯 Win32 原生控件，无任何第三方 UI 库：四个信息面板（考试日程 / 打铃节点 / 音频文件 / 运行日志）各自带标题行与细分隔线，面板内的日程行、状态标记、按钮全部自绘。时间选择器与弹出月历也是自绘窗口类（`EBTimePick` / `EBCalendar`），不使用 `SysDateTimePick32`。应用清单启用 comctl32 v6 视觉样式，运行时读取屏幕 DPI 并按比例缩放全部坐标，高 DPI 下不糊不挤。

### 6. 低占用设计

- **按需轮询**：空闲时定时器 `1 s`，启动监测后自动切到 `200 ms`，任务结束再降回 `1 s`；
- **按需重绘**：时钟、日期、倒计时、状态胶囊都先比较文本与配色，变化时才 `SetWindowText` + `InvalidateRect`，静置时几乎不产生绘制；
- **无闪烁**：主窗口 `WM_ERASEBKGND` 直接返回，绘制只在 `WM_PAINT` 内一次完成，并启用 `WS_CLIPCHILDREN` 避免子控件区域重绘；
- **无对象泄漏**：所有 GDI 对象用后即删，实测连续重绘 100 次，GDI 对象数恒定不变；
- **实测**（Windows 10，125% 缩放）：空闲 CPU `0%`，私有内存约 `4 MB`，工作集约 `24 MB`，长时间静置数值不增长；GDI 对象 49、USER 对象 59 保持不变。

### 7. 稳定性设计

这套程序的使用场景是几千人规模的考场，出错代价很高，因此按「关键任务」标准逐项消除单点故障：

- **单实例保护**：启动时先检测同名互斥量与同名窗口，若已有实例在运行则唤醒并提示，避免两份进程在同一节点各响一次铃；
- **防休眠**：进入监测后调用 `SetThreadExecutionState` 阻止系统休眠与熄屏，本轮结束或急停时立即释放；
- **配置原子写入**：先写 `config.ini.tmp`，`FlushFileBuffers` 落盘后再用 `MoveFileExW` 原子替换，异常断电不会留下半截配置文件；
- **运行日志落盘**：所有关键动作同步追加到 `%APPDATA%\ExamBell\exam_bell.log`（UTF-8，超过 2 MB 自动滚动为 `.log.1`），界面里的日志被清空也不影响事后追查；
- **崩溃留证**：`SetUnhandledExceptionFilter` 捕获未处理异常，把异常码与出错地址写进日志；
- **铃声队列**：多个节点同一分钟到点时不再打断上一段音频，而是排队依次播报，前一段播完自动播下一段；
- **播放看门狗**：音频 1.2 秒内未进入播放状态即判定失败、改走系统提示音；单段播放超过 10 分钟强制结束，保证后续节点不被卡死。

## 已知限制

- 三个公开时间源都可能因网络策略、接口限流或接口变更而失效；全部失效时程序自动回退本机时间，此时打铃精度取决于本机时钟是否准确。
- 音频播放依赖系统默认输出设备，请在正式使用前确认音量与输出设备。
- 监测进行中可继续添加新场次，但**删除与清空**仍被锁定（避免误删正在执行的场次），同时锁定打铃间隔设置（已排期节点不因中途改间隔而失效），需先急停或等本轮结束。
- 最多可排 24 场，开始时间精确到分钟（秒固定为 `00`）。
- 界面为固定布局，不支持窗口缩放（按 96 DPI 设计，运行期随系统 DPI 等比缩放）。
